SYMMETRIC KEY CIPHERS
Q1
Differentiate block cipher and stream cipher.

Block ciphers and stream ciphers are the two main categories of symmetric encryption algorithms. They differ in how they process plaintext.

Stream Cipher

  • Encrypts data one bit or one byte at a time.
  • Uses a keystream generator to produce a bit stream that is XORed with plaintext.
  • The keystream is generated from a secret key shared by both users.
  • Ciphertext is same length as plaintext — no padding needed.
  • Can operate in real time (suitable for streaming data).
  • Examples: RC4, Vernam cipher, autokeyed Vigenère cipher.

Block Cipher

  • Encrypts data in fixed-size blocks (typically 64 or 128 bits).
  • The entire block is processed together to produce a ciphertext block of equal length.
  • The same algorithm and key are used for each block.
  • Requires padding if the last block is not a full block.
  • More widely used in network-based symmetric applications.
  • Examples: DES, AES, 3DES.

Q2
Explain critical aspects of block cipher design principles.

A block cipher must be designed carefully to resist cryptanalytic attacks. The three critical design aspects are:

1. Number of Rounds

The number of rounds determines how many times the encryption transformation is applied. More rounds = more security.

  • The greater the number of rounds, the harder it is to perform cryptanalysis.
  • The criterion: number of rounds should be chosen so that known cryptanalytic attacks require more effort than a brute-force key search.
  • DES uses 16 rounds; AES uses 10, 12, or 14 rounds depending on key size.

2. Design of the Function F

The function F is the heart of a Feistel block cipher and provides confusion.

  • Nonlinearity: F must be nonlinear. The more nonlinear F is, the harder cryptanalysis becomes.
  • Avalanche Effect: A change in one input bit should cause changes in many output bits. This provides diffusion.
  • Bit Independence Criterion (BIC): Output bits j and k should change independently when any single input bit i is inverted, for all i, j, k.
  • F must be difficult to "unscramble" — substitution performed by F must be hard to reverse without the key.

3. Key Schedule Algorithm

The key schedule generates a subkey for each round from the main key.

  • Subkeys should be chosen to maximize the difficulty of deducing individual subkeys.
  • Should make it difficult to work back to the main key from subkeys.
  • The schedule must guarantee key/ciphertext Strict Avalanche Criterion (SAC) and Bit Independence Criterion (BIC).
Summary: Good block cipher design balances confusion (obscuring relationship between key and ciphertext), diffusion (spreading influence of plaintext bits), and computational hardness.
Q3
Explain the structure and working of the Data Encryption Standard (DES).

Overview of DES

  • DES is a block cipher — encrypts data in 64-bit blocks.
  • Uses a 56-bit key (initially 64 bits, every 8th bit is discarded).
  • Same algorithm and key used for both encryption and decryption.
  • Was the standard before AES (2001).

Broad Steps in DES

64-bit Plaintext
↓
Initial Permutation (IP)
↓
32-bit LPT  |  32-bit RPT
↓ (16 Rounds each with subkey)
Final Permutation (FP)
↓
64-bit Ciphertext

Steps Inside Each Round (16 Rounds)

Step 1: Key Transformation (Compression Permutation)

  • 64-bit key → 56-bit by dropping every 8th bit.
  • 56-bit key split into two 28-bit halves, circularly shifted left by 1 or 2 positions.
  • 48 of the 56 bits selected → forms the 48-bit subkey for the round.

Step 2: Expansion Permutation

  • RPT (32 bits) is expanded to 48 bits by repeating certain bits.
  • The 48-bit expanded RPT is XORed with the 48-bit subkey.

Step 3: S-Box Substitution

  • The 48-bit XOR output is fed into 8 S-boxes (each takes 6 bits, outputs 4 bits).
  • Produces a 32-bit output — provides confusion.

Step 4: P-Box Permutation

  • The 32-bit S-box output is permuted using a P-box table.
  • Provides diffusion (bit positions are rearranged).

Step 5: XOR and Swap

  • P-box output is XORed with LPT → becomes new RPT.
  • Old RPT becomes new LPT (swap).

Final Permutation

After 16 rounds, LPT and RPT are rejoined and a final permutation (inverse of IP) is applied to produce the 64-bit ciphertext.

Key Fact: DES uses substitution (S-boxes) for confusion and permutation (P-boxes) for diffusion. The 16 rounds ensure sufficient complexity to resist attacks.
Q4
Illustrate the encryption process in Advanced Encryption Standard (AES).

Overview of AES

  • Published by NIST in 2001. Replaces DES as the standard.
  • Block size: 128 bits (16 bytes) — fixed.
  • Key sizes: 128, 192, or 256 bits → AES-128, AES-192, AES-256.
  • Number of rounds: 10, 12, or 14 depending on key length.
  • All operations performed on 8-bit bytes over finite field GF(2⁸).

AES State Representation

The 128-bit input block is arranged as a 4×4 matrix of bytes called the State. The key is also expanded into a key schedule array.

Four Transformation Stages Per Round

1. SubBytes (Substitution)

  • Each byte of the State is replaced using an S-box lookup table.
  • Provides nonlinearity (confusion).
  • The S-box is constructed using the multiplicative inverse in GF(2⁸).

2. ShiftRows (Permutation)

  • Each row of the 4×4 State matrix is cyclically shifted left.
  • Row 0: no shift; Row 1: 1 byte left; Row 2: 2 bytes; Row 3: 3 bytes.
  • Provides inter-column diffusion.

3. MixColumns (Substitution)

  • Each column of the State is treated as a polynomial and multiplied by a fixed matrix over GF(2⁸).
  • Provides diffusion by mixing bytes within each column.
  • Not applied in the final round.

4. AddRoundKey (XOR with Key)

  • Each byte of the State is XORed with the corresponding byte of the round key.
  • This is the only stage that uses the key.
  • Applied at the beginning (Round 0) and after every round.

AES Encryption Structure

Initial Transformation:   AddRoundKey (Round 0 key)
Rounds 1 to N-1:          SubBytes → ShiftRows → MixColumns → AddRoundKey
Final Round N:            SubBytes → ShiftRows → AddRoundKey  (no MixColumns)

Key Lengths & Rounds

AlgorithmKey Length (bytes)No. of Rounds
AES-1281610
AES-1922412
AES-2563214

Advantages of AES

  • Symmetric and parallel structure — flexible implementation.
  • Works well on modern processors (RISC, Pentium, parallel).
  • Suitable for smart cards and embedded systems.
Q5
Explain the various modes of operation of block ciphers.

A mode of operation is a technique for applying a block cipher to sequences of data blocks. NIST defines five modes:

1. Electronic Codebook (ECB)

  • Simplest mode — each plaintext block encrypted independently with the same key.
  • Same plaintext block → same ciphertext block (deterministic).
  • Weakness: patterns in plaintext are visible in ciphertext.
  • Application: Secure transmission of single values (e.g., encryption keys).

2. Cipher Block Chaining (CBC)

  • Each plaintext block is XORed with the previous ciphertext block before encryption.
  • An Initialization Vector (IV) is used for the first block.
  • Same plaintext block → different ciphertext (hides patterns).
  • Application: General-purpose block transmission, authentication.

3. Cipher Feedback (CFB)

  • Converts block cipher into a stream cipher.
  • Preceding ciphertext is used as input to the encryption algorithm to produce pseudorandom output, which is XORed with plaintext.
  • Input processed s bits at a time.
  • Application: General-purpose stream-oriented transmission, authentication.

4. Output Feedback (OFB)

  • Similar to CFB, but the encryption algorithm output (not ciphertext) is fed back.
  • Full blocks are used. Keystream is independent of plaintext.
  • Application: Stream-oriented transmission over noisy channels (e.g., satellite).

5. Counter (CTR)

  • Each plaintext block is XORed with an encrypted counter.
  • Counter is incremented for each subsequent block.
  • Allows parallel encryption/decryption.
  • Application: High-speed requirements, general-purpose block transmission.

Q8
Explain the working principle of stream ciphers.

What is a Stream Cipher?

A stream cipher encrypts a digital data stream one bit or one byte at a time by XORing the plaintext with a generated keystream.

Working Principle

Key (K) → Bit-stream Generator → keystream kᵢ
Plaintext (pᵢ) ⊕ keystream (kᵢ) = Ciphertext (cᵢ)
Decryption: cᵢ ⊕ kᵢ = pᵢ (same keystream used)
  • Both sender and receiver share the generating key K.
  • The bit-stream generator is a key-controlled algorithm that produces a keystream.
  • The keystream must be cryptographically strong — computationally infeasible to predict future portions from past portions.
  • One-time pad (Vernam cipher): if keystream is truly random and as long as plaintext, the cipher is unbreakable. But distributing such a long key is impractical.

Properties of a Good Stream Cipher

  • Long period of the keystream (no repeating patterns).
  • Keystream appears statistically random.
  • Sufficient key length to prevent brute force.
  • Ciphertext length = Plaintext length (no padding).

Examples

RC4, ChaCha20, Salsa20, autokeyed Vigenère, Vernam cipher.

Q9
Contrast Electronic Codebook and Cipher Block Chaining with the help of illustration.

ECB — Electronic Codebook

  • Each block encrypted independently.
  • No feedback from previous block.
  • Same plaintext → same ciphertext.
  • Vulnerable to pattern attacks.
  • Parallel encryption possible.
  • No IV needed.

CBC — Cipher Block Chaining

  • Each block XORed with previous ciphertext.
  • Uses Initialization Vector (IV).
  • Same plaintext → different ciphertext.
  • Patterns in plaintext are hidden.
  • Sequential (cannot parallelize encryption).
  • Decryption is parallelizable.

ECB Encryption

P₁ →[Encrypt K]→ C₁
P₂ →[Encrypt K]→ C₂    (each block independent)
Pₙ →[Encrypt K]→ Cₙ

CBC Encryption

P₁ ⊕ IV   →[Encrypt K]→ C₁
P₂ ⊕ C₁   →[Encrypt K]→ C₂   (each block chained to previous CT)
Pₙ ⊕ Cₙ₋₁ →[Encrypt K]→ Cₙ

CBC Decryption

C₁ →[Decrypt K]→ ⊕ IV   = P₁
C₂ →[Decrypt K]→ ⊕ C₁  = P₂
Key Difference: ECB is simple but insecure for patterns. CBC is much stronger because each ciphertext block depends on all preceding plaintext blocks, eliminating repetition.
ASYMMETRIC KEY CIPHERS
Q10
Explain the need for asymmetric key cryptography.

Limitations of Symmetric Cryptography

  • Key Distribution Problem: Both parties must share the same secret key beforehand. Securely distributing the key over an insecure channel is a challenge.
  • Scalability: For n users, n(n-1)/2 unique keys are needed — impractical for large networks.
  • No Non-repudiation: Since both parties share the same key, either could have created a message. There is no way to prove who sent a message.
  • No Digital Signatures: Symmetric keys cannot be used to create digital signatures.

How Asymmetric Cryptography Solves This

  • Uses two mathematically related keys: a public key (shared openly) and a private key (kept secret).
  • Key Distribution: Public keys can be shared openly — no secure channel needed for key exchange.
  • Authentication: A message signed with a private key can be verified by anyone with the public key.
  • Non-repudiation: Only the holder of the private key could have signed the message.
  • Digital Signatures: Enabled by asymmetric keys.

Applications Enabled by Asymmetric Crypto

  • Secure key exchange (Diffie-Hellman)
  • Digital certificates and PKI
  • Email encryption (PGP)
  • HTTPS/TLS handshake
  • Blockchain and digital signatures
Q11
Describe the basic principles of public key cryptosystems.

Public-key cryptography is asymmetric — it uses two separate but mathematically related keys for encryption and decryption.

Six Ingredients of a Public-Key Encryption Scheme

  1. Plaintext: The original readable message fed as input.
  2. Encryption Algorithm: Performs transformations on the plaintext using the key.
  3. Public Key: Used for encryption (shared openly). Anyone can encrypt with it.
  4. Private Key: Used for decryption (kept secret by owner). Only the owner can decrypt.
  5. Ciphertext: Encrypted output — depends on plaintext and key used.
  6. Decryption Algorithm: Accepts ciphertext and private key → recovers plaintext.

Essential Requirements

  • It must be computationally easy to generate a public/private key pair.
  • It must be computationally easy to encrypt using the public key.
  • It must be computationally easy to decrypt using the private key.
  • It must be computationally infeasible to determine the private key from the public key.
  • It must be computationally infeasible to recover plaintext from ciphertext and the public key alone.

How Public Key Encryption Works

1. Alice generates key pair: Public Key PUₐ, Private Key PRₐ
2. Alice publishes PUₐ (in a public registry)
3. Bob encrypts message M using Alice's public key:   C = E[PUₐ, M]
4. Bob sends C to Alice
5. Alice decrypts:  M = D[PRₐ, C]
6. No one else can decrypt because only Alice has PRₐ

Trapdoor One-Way Function

Public key algorithms rely on a trapdoor one-way function — easy to compute in one direction (encryption), computationally infeasible to reverse (decryption) without the trapdoor (private key).

Q12
Explain the working of the RSA algorithm.

RSA (Rivest-Shamir-Adleman) is the most widely used public-key encryption algorithm. Security is based on the difficulty of factoring large numbers.

Key Generation

Step 1: Select two large prime numbers p and q, p ≠ q
Step 2: Calculate n = p × q         (n is the modulus)
Step 3: Calculate φ(n) = (p-1)(q-1) (Euler's totient)
Step 4: Choose e such that:          gcd(φ(n), e) = 1 ; 1 < e < φ(n)
Step 5: Calculate d such that:        d·e ≡ 1 (mod φ(n))
Public Key  PU = {e, n}
Private Key PR = {d, n}

Encryption

Given plaintext M where M < n:
Ciphertext C = Mᵉ mod n

Decryption

Given ciphertext C:
Plaintext M = Cᵈ mod n

Mathematical Basis

RSA is based on Euler's theorem: M^φ(n) ≡ 1 (mod n). Since de ≡ 1 (mod φ(n)), we have M^(ed) ≡ M (mod n), which guarantees decryption recovers the original plaintext.

Q13
Explain the concept of Elliptic Curve Cryptography (ECC).

What is ECC?

Elliptic Curve Cryptography (ECC) is a public-key cryptographic system based on the algebraic structure of elliptic curves over finite fields. It achieves high security with much smaller key sizes compared to RSA.

Elliptic Curve Equation

y² = x³ + ax + b
where the non-singularity condition must hold:
4a³ + 27b² ≠ 0

Security Principle: ECDLP

ECC is based on the Elliptic Curve Discrete Logarithm Problem (ECDLP):

Given points P and Q on the curve such that Q = kP
It is computationally infeasible to find k, even knowing P and Q.

Key Generation in ECC

  1. Select an elliptic curve and a base point P on the curve.
  2. Choose a random integer k → this is the private key.
  3. Compute Q = kP → this is the public key.

ECC Applications

  • ECDH — Elliptic Curve Diffie-Hellman (key exchange)
  • ECDSA — Elliptic Curve Digital Signature Algorithm
  • ECIES — Elliptic Curve Integrated Encryption Scheme

ECC vs RSA Key Size Comparison

Advantages of ECC

  • Equivalent security with much smaller keys.
  • Faster key generation and lower computational cost.
  • Reduced memory and power consumption.
  • Ideal for IoT, mobile devices, smart cards, embedded systems.
Q14
Explain the characteristics of lightweight cryptographic algorithms.

What is Lightweight Cryptography?

Lightweight cryptography refers to cryptographic algorithms designed for resource-constrained devices such as IoT sensors, RFID tags, smart cards, and embedded systems that have limited memory, CPU, energy, and bandwidth.

Need for Lightweight Cryptography

Traditional algorithms (AES, RSA) require large memory, high computational power, and significant energy. Constrained devices cannot support these. Lightweight cryptography provides adequate security with minimal resource usage.

Characteristics

  • Small key size: Typically 80–128 bits.
  • Low memory footprint: Small code size and RAM usage.
  • Reduced computational complexity: Simple operations (XOR, shifts, modular addition).
  • Low power consumption: Critical for battery-powered devices.
  • Fast execution: Optimized for limited hardware.

Types of Lightweight Cryptographic Algorithms

TypePurposeExamples
Symmetric KeyData confidentialitySPECK, PRESENT, SIMON, AES (lightweight)
Asymmetric KeyKey exchange, authenticationECC, lightweight RSA
Hash FunctionsData integrityPHOTON, SPONGENT, QUARK

SPECK – A Lightweight Block Cipher

  • Developed by the NSA; highly efficient for hardware and software.
  • Uses ARX structure: Addition (mod 2ⁿ), Rotation (cyclic shifts), XOR.
  • Variants: SPECK32/64, SPECK64/128, SPECK128/256.
  • Each round: rotate word left by a bits → add mod 2ⁿ → XOR with round key → rotate other word right by b bits.

Applications

  • Internet of Things (IoT)
  • RFID systems
  • Wireless sensor networks
  • Smart healthcare devices
  • Industrial control systems
Q15
Analyze a communication system and determine whether a block cipher or stream cipher is more appropriate, with justification.

Analysis Framework

The choice depends on the nature of the data, real-time requirements, and the error characteristics of the channel.

Use Stream Cipher When:

  • Real-time streaming data — e.g., voice calls, video conferencing. Data arrives continuously and must be encrypted immediately.
  • Unknown message length — stream ciphers don't need padding.
  • Noisy channels — a bit error affects only that bit (no error propagation).
  • Low-latency requirement — stream ciphers can process one byte at a time.
  • Examples: Cellular voice (A5/1 in GSM), RC4 in WEP.

Use Block Cipher When:

  • File and database encryption — data is available as whole blocks.
  • Message authentication — CBC-MAC, HMAC.
  • Secure key storage or transmission — ECB for single values.
  • Network protocols — TLS, IPSec, VPN use AES.
  • Higher security requirements with well-defined block boundaries.
  • Examples: AES in TLS/HTTPS, DES in legacy systems.
Conclusion: For a real-time voice communication system, a stream cipher is more appropriate due to low latency, no padding, and single-bit error containment. For a file storage or network protocol system, a block cipher (e.g., AES-CBC or AES-CTR) is more appropriate.

Q19
Comment on the security of RSA.

Security Basis of RSA

RSA security relies on the computational difficulty of factoring large composite numbers — specifically the modulus n = p×q.

1. Hardness of Integer Factorization

  • It is easy to multiply two large primes (forward direction).
  • But given only n, it is computationally infeasible to find p and q for large n.
  • If an attacker factors n, they can compute φ(n) and then find d.

2. Private Key Secrecy

  • d cannot be computed from (e, n) alone without knowing φ(n).
  • Computing φ(n) requires knowing p and q, which requires factoring n.

3. Key Size Matters

  • 1024-bit keys: considered insecure today.
  • 2048-bit keys: current minimum recommendation.
  • 4096-bit keys: used for long-term security.

4. Resistance to Brute Force

  • The key space is enormous — trying all possible d values is infeasible.

5. Known Weaknesses

  • Small exponent attack: If e is too small, attacks using cube roots are possible.
  • Common modulus attack: Never use the same n for two key pairs.
  • Timing attacks: Side-channel attacks on implementation.
  • Quantum threat: Shor's algorithm on a quantum computer can factor n efficiently — RSA would be broken by large-scale quantum computers.
Recommendation: Use at least 2048-bit keys. For post-quantum security, consider lattice-based or hash-based alternatives.
